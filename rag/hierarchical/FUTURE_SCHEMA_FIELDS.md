# 🔮 미래 확장 가능한 스키마 필드들

## 📋 개요

현재 법령 스키마는 실용성을 위해 **핵심 15개 필드**로 축소되었습니다.
이 문서는 향후 시스템 고도화 시 추가할 수 있는 필드들을 정리한 것입니다.

---

## ❌ 제거된 필드들 (33개)

### 🧮 **자동 계산 가능한 통계 필드들 (4개)**

#### `child_count` (INT64)
- **설명**: 직접 자식 노드 수
- **제거 이유**: 실시간 쿼리로 계산 가능
- **복원 시 활용**: 성능 최적화 (캐싱)
```sql
SELECT COUNT(*) FROM collection WHERE parent_node_id = 'target_node'
```

#### `descendant_count` (INT64) 
- **설명**: 전체 하위 노드 수
- **제거 이유**: 복잡한 계산이지만 쿼리로 가능
- **복원 시 활용**: 대용량 데이터에서 성능 향상

#### `tree_depth` (INT64)
- **설명**: 서브트리 최대 깊이  
- **제거 이유**: hierarchy_level로 충분
- **복원 시 활용**: 복잡한 위계 구조 분석

#### `sibling_order` (INT64)
- **설명**: 형제 노드 내 순서
- **제거 이유**: 검색에 거의 활용되지 않음
- **복원 시 활용**: 정확한 법령 순서 재현

---

### 🔗 **중복/겹치는 필드들 (5개)**

#### `law_title` (VARCHAR, 256)
- **설명**: 법령명
- **제거 이유**: `title` 필드와 완전 중복
- **복원 시 활용**: 문서 제목과 법령명을 구분해야 할 때

#### `article_title` (VARCHAR, 256)
- **설명**: 조문 제목  
- **제거 이유**: `title` 필드로 통합 가능
- **복원 시 활용**: 조문별 세부 제목 관리

#### `legal_keywords` (JSON)
- **설명**: 법률 전문 키워드
- **제거 이유**: `keywords` 필드와 중복
- **복원 시 활용**: 일반 키워드와 법률 키워드 분리

#### `title_embedding` (FLOAT_VECTOR, 1024)
- **설명**: 제목 임베딩 벡터
- **제거 이유**: content_embedding으로 충분
- **복원 시 활용**: 제목 기반 정밀 검색

#### `updated_at` (VARCHAR, 32)
- **설명**: 최종 수정일
- **제거 이유**: 법령은 변경되지 않음
- **복원 시 활용**: 동적 콘텐츠 관리

---

### 🤖 **자동 생성 가능한 필드들 (3개)**

#### `content_hash` (VARCHAR, 64)
- **설명**: 내용 해시값 (중복 검사용)
- **제거 이유**: 필요시 실시간 계산 가능
- **복원 시 활용**: 대용량 중복 검사 성능 향상
```python
hashlib.sha256(content.encode()).hexdigest()
```

#### `summary` (VARCHAR, 2048)
- **설명**: 내용 요약
- **제거 이유**: AI 모델로 실시간 생성 가능
- **복원 시 활용**: 빠른 요약 제공, 검색 결과 미리보기

#### `keywords` (JSON)
- **설명**: 추출된 키워드 배열
- **제거 이유**: NER/키워드 추출 모델로 실시간 생성
- **복원 시 활용**: 키워드 기반 검색 최적화

---

### 🏛️ **현실적으로 입력 어려운 메타데이터 (9개)**

#### `ministry` (VARCHAR, 64)
- **설명**: 소관부처
- **제거 이유**: 수동 입력 어려움, 법령별 매핑 DB 필요
- **복원 시 활용**: 부처별 법령 분류, 업무 담당자 연결

#### `enactment_date` (VARCHAR, 32)
- **설명**: 제정일 (YYYY-MM-DD)
- **제거 이유**: 텍스트 파싱으로 추출 가능
- **복원 시 활용**: 시계열 분석, 법령 연혁

#### `enforcement_date` (VARCHAR, 32)
- **설명**: 시행일 (YYYY-MM-DD)  
- **제거 이유**: 텍스트 파싱으로 추출 가능
- **복원 시 활용**: 유효성 검증, 적용 시점 확인

#### `amendment_date` (VARCHAR, 32)
- **설명**: 최종 개정일
- **제거 이유**: 실시간 추적 불가능
- **복원 시 활용**: 법령 최신성 관리

#### `interpretation_notes` (JSON)
- **설명**: 해석 지침/유권해석
- **제거 이유**: 별도 유권해석 DB 연동 필요
- **복원 시 활용**: 법령 해석 가이드 제공

#### `precedents` (JSON)
- **설명**: 관련 판례 정보
- **제거 이유**: 판례 DB 연동 시스템 필요
- **복원 시 활용**: 판례 기반 법령 이해

#### `practical_guidelines` (JSON)
- **설명**: 실무 가이드라인
- **제거 이유**: 실무 가이드 별도 관리 체계 필요  
- **복원 시 활용**: 실무진 업무 지원

#### `subject_classification` (VARCHAR, 128)
- **설명**: 주제별 분류 (행정/민사/형사/상사)
- **제거 이유**: AI 텍스트 분류로 자동화 가능
- **복원 시 활용**: 법 분야별 전문 검색

#### `target_audience` (VARCHAR, 64)
- **설명**: 적용 대상 (일반인/사업자/공무원)
- **제거 이유**: AI 분류로 자동화 가능
- **복원 시 활용**: 사용자별 맞춤 검색

---

### 🔬 **고급 분석 기능 필드들 (7개)**

#### `penalty_info` (JSON)
- **설명**: 벌칙 정보 (벌금, 징역 등)
- **제거 이유**: 복잡한 벌칙 구조 파싱 로직 필요
- **복원 시 활용**: 위반 시 처벌 수준 안내
```json
{
  "fine_amount": "300만원 이하",
  "imprisonment": "1년 이하", 
  "penalty_type": "과태료"
}
```

#### `related_laws` (JSON)
- **설명**: 관련 법령 목록
- **제거 이유**: 법령간 관계 분석 고도화 필요
- **복원 시 활용**: 법령간 연관성 탐색
```json
[
  {"law_name": "정보통신망법", "relation": "상위법"},
  {"law_name": "개인정보보호법 시행령", "relation": "하위법"}
]
```

#### `referenced_articles` (JSON)
- **설명**: 인용/참조 조문들
- **제거 이유**: 단순 패턴 매칭으로 충분
- **복원 시 활용**: 조문간 참조 관계 시각화
```json
[
  {"article": "제2조", "type": "정의참조"},
  {"article": "제25조", "type": "준용"}
]
```

#### `cross_references` (JSON)
- **설명**: 상호 참조 정보  
- **제거 이유**: 양방향 참조 구축 복잡
- **복원 시 활용**: 법령 네트워크 분석

#### `article_type` (VARCHAR, 64)
- **설명**: 조문 유형 (정의/목적/범위/절차/벌칙)
- **제거 이유**: 검색에 실질적 활용 부족
- **복원 시 활용**: 조문 성격별 분류 검색

#### `legal_effect` (VARCHAR, 32)
- **설명**: 법적 효력 (의무/권리/금지/허용/절차)
- **제거 이유**: 법적 효력 분석 고도화 필요
- **복원 시 활용**: 권리/의무 관계 명확화

#### `source_info` (JSON)
- **설명**: 원본 소스 정보
- **제거 이유**: 검색에 직접 활용되지 않음
- **복원 시 활용**: 출처 추적, 신뢰성 검증

---

### 🏗️ **구조적 메타데이터 (5개)**

#### `node_type` (VARCHAR, 64)
- **설명**: 노드 타입 (chapter/section/article/paragraph)
- **제거 이유**: hierarchy_level로 타입 판단 가능
- **복원 시 활용**: 명시적 노드 타입 구분

#### `provision_type` (VARCHAR, 32)
- **설명**: 조문 구분 (본칙/부칙/별표/별지)
- **제거 이유**: 실제 검색에 활용도 낮음
- **복원 시 활용**: 법령 구조별 세밀한 검색

#### `chapter_info` (JSON)
- **설명**: 편/장/절 정보
- **제거 이유**: hierarchy_path에 정보 포함 가능
- **복원 시 활용**: 상세한 구조 정보 표시

#### `subitem_number` (VARCHAR, 32)
- **설명**: 목 번호 (가., 나., 다.)
- **제거 이유**: 사용 빈도 매우 낮음
- **복원 시 활용**: 최세밀 단위 검색

#### `structure_metadata` (JSON)
- **설명**: 구조적 메타데이터 덤프
- **제거 이유**: 실용성 부족
- **복원 시 활용**: 디버깅, 구조 분석

## 🔄 **복원 우선순위**

### **🚀 1순위 (성능 최적화)**
- `content_hash` - 대용량 중복 검사
- `child_count` - 통계 캐싱
- `summary` - 검색 결과 미리보기

### **📈 2순위 (고급 기능)**  
- `enactment_date`, `enforcement_date` - 시계열 분석
- `penalty_info` - 위반 시 처벌 안내
- `related_laws` - 법령 연관성

### **🔬 3순위 (전문 기능)**
- `interpretation_notes` - 유권해석 연동
- `precedents` - 판례 연동  
- `ministry` - 부처별 분류

### **⚡ 4순위 (성능 미세 조정)**
- `descendant_count`, `tree_depth` - 복잡한 위계 분석
- `title_embedding` - 제목 기반 정밀 검색
- `cross_references` - 법령 네트워크

---

## 💡 **구현 시 고려사항**

### **자동화 우선**
대부분의 필드는 **수동 입력보다 자동 추출/생성**이 효율적

### **외부 연동 필요**
- 부처 정보: 행정기관 DB
- 판례 정보: 대법원 판례 DB  
- 유권해석: 각 부처 유권해석 DB

### **성능 vs 기능**
- 저장 용량 증가 vs 검색 성능 향상
- 실시간 계산 vs 사전 계산된 값
